项目简介

流火实验室（Starfall Lab，简称流火）是《红色警戒 2：尤里的复仇》的 DLL 扩展。模组作者可以通过 INI 配置单位被动能力和战场中的三选一科研升级。

使用指南

第一次配置可以从单位被动或科研项目入手。已经知道字段名时，按 / 搜索整本手册。

科研卡没有出现或被动未生效时，查看游戏根目录的 Starfall.log。科研配置错误会列出段名、字段、读取到的值和原因；可定位到独立 Starfall.ini 的字段还会标出行号。来自 rulesmd.ini、地图或包含文件的字段按游戏合并后的规则检查。

Trigger / Action单位自带被动 ↗从灰熊击杀回血开始，配置触发条件和结果。Effect / TargetTypes注册科研项目 ↗设置三选一候选、国家限制和受益兵种。

单位自带被动

简要介绍

三个 INI 段怎样配合

给单位配置自带被动，需要用同一个被动 ID 串起三个 INI 段。以 SF_KillHeal 为例：

  1. 注册被动　在 [Starfall.PassiveTypes] 中用一个空闲数字键登记 SF_KillHeal。数字是注册表的位置，后面引用技能时填写 SF_KillHeal。
  2. 定义规则　新建同名段 [SF_KillHeal]，写明什么时候判断、哪些情况算数、满足后做什么。
  3. 绑定单位　在兵种段 [MTNK] 中填写 Starfall.Passives=SF_KillHeal。这样各方的灰熊都自带该技能。已有其他被动时，用英文逗号把新 ID 追加到原列表。地图兵种段也可用 Starfall.Passives 追加本图专属被动，绑定会随存档保存。

额外补充说明

受伤前事件同步修改待扣生命，受伤后事件按实际损失的生命结算。一次范围攻击伤到三个单位，可产生三次造成伤害事件。击杀事件记录的伤害量为 0，因此击杀回血应使用固定值。事件型能力记录事件发生时的血量、电力和隐形状态，随后结算；除死亡事件外，结算时持有者须存活。死亡事件保留死亡位置和所属方，因此可以在自身原位置引爆弹头，或给原所属玩家发钱；死亡后对自己回血不能复活。部署、晋升建议保持默认的阵营与类别筛选 All。

不同条件须同时满足；一个筛选字段列多个值时，满足任一值即可。先筛选、检查冷却，再累计次数。到达门槛就清零并判定概率。概率失败，或满血导致实际治疗量为 0，都不开始冷却。比如 Count=3（完整键名为 Condition.Count）配 Chance=30%，就是每三次有效事件获得一次 30% 的机会。

持续的状态条件

简要介绍

设置 Trigger=WhileState 后，单位在场时每帧检查状态。条件成立并达到等待时间后应用持续结果，条件中断时撤销。下列条件可同时用于事件型被动和 WhileState。同一技能中填写多个条件时，须全部满足。

检测附近单位时，按指定范围、阵营和单位类型统计数量，再判断数量是否达到门槛。

额外补充说明

Condition.Formula 结果非零表示满足；比较返回 1 或 0，可以用乘法组合条件。Self.Ammo 是当前弹药（无限弹药为 -1），Self.Passengers 是当前乘客人数。持续状态读取当前值，事件读取发生时快照。缺少目标、除零或无效结果视为不满足，状态等待计时重置。

原有生命、弹药与乘客数量条件已经移除，旧配置需要改用公式。半血及以下写 Condition.Formula=$(Self.Health <= Self.MaxHealth * 50%)；弹药为 1～3 写 Condition.Formula=$((Self.Ammo >= 1) * (Self.Ammo <= 3))。

单位不在地图时。当游戏将进入建筑或载具的单位标记为不在地图上或处于 InLimbo 时，流火暂停该单位的 WhileState 条件计算并撤销对应的持续修正。单位返回地图后，若被动仍有效且条件满足，持续修正会重新生效；配置的状态等待时间需要重新计算。OnInterval 在此期间不触发，返回后从头计算周期。之前通过事件累计获得的属性变化独立保存，不会仅因临时被动到期而自动撤销。

WhileState 段支持 Trigger、上述状态条件、等待秒数、持续修正和动画字段。混入 Action.*、Action、Filter.*、Chance、Cooldown 或 Condition.Count 等不兼容字段时，整项技能不加载。可在游戏根目录的 Starfall.log 查看冲突字段。

用 Condition.Nearby.Range 指定 1～32 格的整数半径，按地图格的平面圆形范围统计。持有者自己不计，跨格建筑和重复枚举的对象只计一次。非友方隐形单位须在本方探测覆盖内，伪装单位须能被本方识破。

大规模对局可缩小检测半径或延长扫描间隔，以减少扫描次数和范围。

消耗乘客时

ConsumePassenger 消耗一名乘客后，运输单位的 OnPassengerConsumed 被动触发。Self 为运输单位，Target.Health、Target.MaxHealth 和 Target.Cost 为乘客消耗前的快照；Self.Passengers 为消耗后的剩余数量。

流火在消耗前记录直属乘客实际持有的被动及层数。将上例的消化被动替换为下例，就会从列表中的每项被动最多夺取 2 层。0 层被动也可整项获得。

也可在同一组 Actions 中先消耗、再夺取。后续动作和运输单位的消耗事件共用这名乘客的剩余层数。每次夺取只扣除实际转移的部分；每名乘客单独记录。事件结算完毕后，未夺取的部分随记录释放。

每次移除乘客列表首位，通常是最后进入的乘客。如果首位乘客也是载具，会从内向外消耗它和全部嵌套乘客，外层运输单位只触发一次 OnPassengerConsumed。Target.Health、Target.MaxHealth 和 Target.Cost 只取这名直属乘客消耗前的值。正常装载时，被寄生的单位无法登车。若运输单位空载，或现有乘客列表异常（如强制装载了被寄生的乘客），动作失败，同一 Actions 列表后续动作停止，之前动作不回滚。成功后同一列表的后续公式使用被消耗乘客的 Target 快照；其他被动仍读取原事件对方。乘客已移除，不能作为需要存活单位的动作目标。建筑独立驻军不属于乘客列表。

事件在移除后排队，待处理事件及快照随存档保存。它只由流火的 ConsumePassenger 产生，不覆盖游戏或其他扩展的消耗行为；流火不会因此主动生成死亡或击杀被动事件。

部署支援光环

把 SF_SupportAura 绑定给能架设的单位。架设后，5 格内符合条件的己方和盟友单位获得 20% 装甲加成。将 Modifier.Aura.Range 改为 -1 即覆盖全图，阵营和类型筛选仍然生效。

每 15 个游戏帧更新一次范围内的单位。来源死亡、被移除或持续条件中断时撤回该来源。同名被动由多个光环、单位自带、科研或临时授予共同提供时只生效一份，最后一个来源消失才失去。重叠覆盖期间不会重复触发 OnPassiveGained，完全离开后再次获得可重新触发。击杀回血等已经结算的事件结果会保留。

建筑生命至少为一半时，电力乘以 0.75。同一个被动绑给耗电 40 点的兵营，耗电降到 30 点；绑给供电 200 点的电厂，供电降到 150 点。

电力倍率只作用于持有被动的建筑。旧配置中的 Modifier.PowerOutputMultiplier 和 Modifier.PowerDrainMultiplier 须改为 Modifier.PowerMultiplier。多个被动的电力倍率相乘，按建筑的实际电量计算并四舍五入到整数。0 表示供电或耗电降为零，条件结束后恢复。用所属方是否缺电作条件时，如果效果本身会改变供电状态，倍率可能反复启停。

持续获得隐形能力

静止连续两秒后允许隐形；移动后撤回这一来源并重置等待时间。须先注册并绑定被动。此效果保留原生隐形延时、CloakStop、开火和探测判定，不会立即强制隐形或变得不可探测。多个来源叠加，天生、宝箱及其他仍有效来源保留；离场时暂停，存读档保留能力与等待进度。不要仅用 Condition.SelfCloak=Uncloaked 作为条件，以免获得隐形后立即失去能力而反复切换。

部署免疫

在部署期间免疫常规生命值伤害；可加 Condition.StateDurationSeconds=2 等待两个游戏秒。绕过防御的强制伤害（如流火自毁）仍按引擎规则执行。弹头附加状态和第三方护盾有各自的判定。

心控免疫仅影响持有者，条件中断后恢复原有判定，状态随存档保存；生效前的心控不会自动解除，心灵控制器伤害不受影响。Ares 永久心控目前适配《远征》使用的 Ares 3.0p1，不兼容时记录 Starfall.log。其他扩展直接改换所属方的特殊逻辑（包括 Phobos ChangeOwner.SetAsMindControl）和地图脚本强制易主不属于已适配的心控入口。

主槽对应索引 0，副槽对应索引 1。普通双武器单位只有一个槽被禁用时，会尝试选用另一把已配置的武器；射程、弹药等仍按游戏规则。特殊多武器、乘员炮塔和盖特阶段沿用游戏原选槽规则。多个生效技能同时修改同一槽时，任一禁用都会阻止发射；多个替换按技能处理顺序取最后一个，某项退出后回到仍有效的替换或当前原生武器。原生武器随星级、部署等变化。仅影响该单位的常规武器槽；Action=FireWeapon 仍使用动作里指定的独立武器。

通常至少指定一个状态条件，并配置持续结果或进入状态时播放的触发动画；乘客的 Modifier.TransportPassives 可以省略条件。例如 Condition.Formula=$(Self.Health <= Self.MaxHealth * 30%) 搭配 Modifier.Berserk=yes 表示持有者生命不高于 30% 时陷入混乱。等待时长可用于延迟状态生效。持续状态和等待进度支持存读档。

多结果

单结果沿用 Action=。多结果用 Actions= 引用一个或多个结果段，按英文逗号分隔，按书写顺序执行。同一结果被列两次就执行两次。只有主技能需要注册和绑定，结果段可跨技能复用。

结果段只填写 Action 和相应的 Action.* 字段。次数、概率和冷却写在主技能上。主段使用 Actions 时不能同时填写 Action 或 Action.*，结果段也不能再嵌套 Actions。缺少结果段、空列表项、无效动作或上述冲突都会停用整项技能，并在游戏根目录的 Starfall.log 记录字段。若希望两个结果分别判定概率，可将其配置为两个被动。

每第三次有效击杀共用一次概率判定。通过后，先尝试恢复 50 生命，再在死者附近生成随机箱。满血仍会掉箱。只要一项成功就按主技能开始冷却，全部无效时不进冷却。后一步可以使用上一步改变后的状态；例如先自毁再在自身位置掉箱，会使用持有者最后的位置。需要存活单位的步骤在对应单位死亡后跳过。

数值公式

简要介绍

用 $(...) 让被动数值随血量、层数、伤害或距离变化。Self 指持有被动的单位，This 指正在执行公式的被动。

参数列表和对应说明

移速、火力、装甲、射程和射速的持续倍率字段，以及对应事件结果的 Action.Percent，都支持公式。建筑的 Modifier.PowerMultiplier 也支持公式。持续倍率 1.25 表示乘以 1.25；事件增量 $(10%) 表示增加 10 个百分点。

治疗、伤害、发放资金和科研点的 Action.Amount 也支持公式，例如 $(min(Event.Damage * 25%, 100))。结果向下取整，负数或超出整数范围时跳过，零无效果。此写法与 Action.PercentOfDamage 互斥。

支持小数、正负号、四则运算、括号和 min(a,b)、max(a,b)、clamp(x,下限,上限)。变量和函数名忽略大小写，1.5% 等于 0.015。

比较运算支持 >、>=、<、<=、==、!=，成立为 1，不成立为 0。比较优先级低于四则运算；多个比较需分别用括号表达，不支持连写。小数相等与不等按计算结果精确比较。

if(条件, 成立值, 不成立值) 中，条件为 0 表示不成立，非 0 表示成立。可嵌套，且只计算被选中的分支；未选中分支中的除零或缺少目标不影响结果。配置仍须满足变量的使用范围，例如 Event.Damage 只能用于伤害事件。

变量含义
Self.Health / Self.MaxHealth持有者的当前生命和最大生命。
Target.Health / Target.MaxHealth对方单位的当前生命和最大生命。造成伤害或击杀时取受害者，受伤或死亡时取攻击者；开火或定时事件取当时的目标，WhileState 取当前目标。部署、晋升和获得被动事件没有对方。
Self.Cost被动持有者当前类型的基础造价，不计折扣。事件读取触发时的造价，持续状态读取当前造价。没有目标时也能使用。例如 Action.Amount=$(Self.Cost * 10%) 按自身造价的 10% 计算。
Target.Cost对方单位类型在当前规则中的基础造价 Cost，不计国家、工业工厂或科研折扣。事件触发时记录造价，持续状态读取当前目标的造价。
This.Stack正在执行公式的被动层数。
Self.Ammo当前弹药；无限弹药为 -1。事件读取快照。
Self.Passengers当前乘客数量，空载为 0。事件读取快照。
Event.Damage受伤后事件读取实际损失生命；OnBeforeDealDamage、OnBeforeTakeDamage 依次读取当前待扣生命值，含前面动作的修改。护盾完全吸收伤害时没有损血事件。
Event.Distance持有者与对方的水平直线距离，以格为单位，可含小数，忽略高度。造成伤害或击杀时取受害者，受伤或死亡时取攻击者，开火或定时事件取当时的目标（可为地面格）。WhileState 取当前目标。

每个项目 ID 对应一张科研卡。注册项目后，在同名段设置卡面内容、候选资格和购买结果。

参数列表和对应说明

注册项目 [Starfall.ResearchTypes]

在 [Starfall.ResearchTypes] 用空闲数字键登记项目 ID，再创建同名项目段。数字键用于注册，前置研究与存档使用右侧的项目 ID。同一个 ID 重复登记只算一个项目。未注册项目时，科研项目列表为空。

单个项目段 [项目ID]

Countries 筛选能看到卡片的国家，TargetTypes 指定获得效果的单位。

额外补充说明

先按国家和工业工厂等原有修正得出基准价，再合计科研百分比，最后加上固定金额。结果四舍五入，最低为 0。例如原价 700，同时获得 −20% 和 −100 后售价为 460。订单在开工时锁价，取消时退还已付金额。读档按玩家的已购项目恢复修正。

单位转换不再要求 Ares。没有加载 Phobos 时，流火使用内置转换，保留单位身份、所属方、星级和被动状态，按原生命比例调整生命，并保留额外生命上限。加载 Phobos 时，流火使用其公开的 ConvertToType_Phobos 接口，让 Phobos 更新自己的单位数据。不同 Phobos 版本需要自行验证；未提供接口的版本（包括《远征》随附的 Dev Build #36）不支持转换，流火会在 Starfall.log 记录原因。

内置转换暂不支持带子机或奴隶的类型、目标类型具有心控、寄生或超时空武器的情况；受到心控、寄生或超时空攻击，正在部署，或带有子机、奴隶、心控、空袭管理器的单位也会跳过。乘客仍须符合目标类型的容量与体型限制；有乘客时，开放舱和炮手设置须一致。使用其他扩展时，其额外附着效果和类型相关状态需另行验证。

科研转换只处理地图上存活且满足类型、地形、乘客容量等条件的己方单位，其他单位跳过。接口不可用、类型无效或移动器 Locomotor 不同时，这类项目不进入候选。没有合适目标或全部转换失败时无法购买，不扣科研点；至少一个转换成功即购买成功。转换不影响之后生产的单位。被动结果 Transform 采用同样的转换路径和限制。

效果按首次出现的顺序执行，同一效果段 ID 重复填写时只执行一次。任何效果配置无效、缺失或依赖不可用时，整个项目不进入候选。购买时跳过暂时无法执行的效果（如没有可转换单位或科技已解锁），其余效果继续执行；至少一项成功才扣点并记录研究，已跳过的即时效果不会在以后补发。被动效果作用于购买者当前和未来符合类型的单位。效果之间不保证事务回滚。Effects 为空时项目无效；未填写 Effects 的旧式单效果配置保持兼容。

列表项目省略 Detail 时，悬浮提示会按顺序显示效果；自定义 Detail 按原文显示，不替换各效果的数值占位符。

悬浮 Detail 可随数值变化。事件被动支持 {amount}、{percent}、{count}、{chance} 和 {cooldown}。多结果被动省略详情时按顺序逐项显示，手写详情中的 {amount} 和 {percent} 取第一项结果的数值。资金项目使用 {credits}。百分比占位符只替换数字，要显示百分号请写 {percent}%。WhileState 可省略 Detail 以显示实际倍率，自定义持续效果详情按原文显示。

Action.OwnerSpawnUnit 可填 Owner 或 Self（发射方，默认）、Neutral、Player1 至 Player8。
RechargeTime使用原版计时，单位为游戏分钟。建筑的 SuperWeapon、SuperWeapon2 可以分别绑定两个超武。

脚本放在 游戏根目录。超武脚本可读取 ctx.point（地图格）、ctx.owner（所属方索引）、ctx.superWeapon（超武标识符）和 ctx.castId（本次发动编号）。ctx.self 和初始 ctx.target 均为 nil。用 ctx:nearbyUnits(ctx.point, radius, filter) 取得单位，再向该单位执行伤害、位移等结果。ctx:schedule 的任务随存档保存，ctx.state 按本次发动隔离。

Lua 事件技能

简介

事件技能在指定的游戏事件发生时调用 Lua 函数。先在 INI 注册技能并绑定兵种，再把返回函数表的 UTF-8 脚本放到游戏根目录。流火会在开局或读档时读取脚本。

参数表

INI 配置

参数或接口说明
[Starfall.PassiveTypes]、Starfall.Passives在注册表列出技能 ID，在兵种段把该 ID 加入自带被动列表。
Trigger、Cooldown选择事件并设置冷却帧数。例如 OnDeploy 表示部署时判定。可用事件见触发时机总览。
Action=RunScript调用脚本。用 Action.Script 指定文件，用 Action.Function 指定该文件返回的函数表中的函数名。多个技能可引用同一函数。
Script.Param.<参数名> → ctx.params.<小写参数名>在技能段填写自定义值。例如 Script.Param.Damage=40 对应数字 ctx.params.damage，Script.Param.Warhead=HE 对应字符串 "HE"。文本保留大小写，缺失键为 nil。定时回调也读取所属技能的当前配置。

Lua 回调接口

参数或接口说明
ctx.self / ctx.target技能持有者与原事件对方。无事件对方时 target 为 nil。单位可用 :alive() 检查当前是否存活。
ctx.damage / ctx.stack事件伤害和触发被动的事件层数。扣血前回调中的 ctx.damage 会随成功的伤害动作更新。
ctx.event事件快照含 selfHealth、selfMaxHealth，以及有单位对方时的 targetHealth、targetMaxHealth。
单位读取id()、alive()、health()、maxHealth()、ammo()、passengers()、rank()、type()、kind()、cost()、owner()、trainable()、hasPassive(id)、stack(id)。使用冒号调用，读取当前实时状态；等级 0、1、2 对应新兵、老兵、精英。
ctx:house(index)返回所属方数据快照：powerOutput 供电、powerDrain 耗电、powerBalance 净电力、credits 可用资金、researchPoints 科研点、index 所属方索引。省略索引时读取技能持有者或超武发射方；可用 ctx:house(ctx.target:owner()) 查询目标所属方。无效索引返回 nil；重新调用可获取最新值。
ctx:nearbyUnits(center, radius, filters)半径为 0～128 格，结果按单位 ID 排序。houses 可选 Self、Allies、Enemies、Neutral、All，默认 All；types 支持 *、@Infantry、@Vehicle、@Aircraft、@Building 和兵种 ID。中心可填单位或地图格坐标。按单位中心的水平距离判定，包含边界。默认排除中心单位，用 includeSelf=true 包含它。
ctx:action(name, args)执行一个流火动作。字段名省略 Action.，例如 Amount、Passive、Levels。Target 可填单位或现有的目标名称。成功返回 true。
ctx:action("ForceMove", args)Offset 填相对偏移，Height 用格，Duration 用帧，Easing 选择水平缓动曲线，Tilt=false 关闭车身倾斜，IgnoreCollision=false 启用途中碰撞。
ctx:runAction(section, overrides)执行已有 INI 单结果段。overrides 可覆盖 Target，超时空传送可覆盖 Destination，强制位移可覆盖其位移参数。该段继续使用本技能触发时机的参数和公式规则。
ctx:actions(list)按列表顺序执行，各项含 Action 和对应字段。共享该次动作上下文；ConsumePassenger 成功后，下一项的 Target="Target" 可以夺取被消耗载员的被动。至少一项成功时返回 true。

示例

美国大兵部署时晋升附近友军

部署时扫描 5 格内可训练的己方和盟友单位，分别晋升一级。扫描半径和晋升级数都取自技能段。

每第三次部署发放资金

将 SF_DeployOrder 注册并绑定给兵种。每第三次部署，脚本调用 INI 中的 SF_Payment，给持有者的所属方增加 500 资金。

额外补充说明

每次调用都有独立的局部变量。跨回调保留单位的技能进度可用 ctx.state，单个定时任务的进度可用 data。待处理事件随存档恢复。

扣血前回调可执行 SetDamage 和 BlockDamage。持续倍率由 WhileState 配置，开火前选武器由 ReplaceWeapon 配置。脚本不能嵌套调用 RunScript。

语法或运行错误可在游戏目录的 Starfall.log 查看文件名和行号。回调报错会结束本次调用，已执行的动作保留。

流火内置 Lua 5.4.8，开放 ipairs 及 table、string、math、utf8 的常用操作。文件访问、系统调用、动态加载和无序表遍历未开放。多人对战须使用相同脚本与规则，对局随机数用 ctx:randomInt 或 ctx:randomPoint。

旧版 Lua 内注册的技能仍可使用。迁移同名技能时，以 INI 中的定义和兵种绑定为准。

简介

Lua 定时任务与随机落点

简介

定时任务让一个技能分多个游戏帧执行。当前回调可以安排下一次回调，在约定的帧数后继续处理。区域轰炸可以借此逐发选择随机落点。

参数表

任务与状态

参数或接口说明
ctx:schedule(frames, callbackName, data)安排一次回调并返回任务 ID。frames 是正整数游戏帧。callbackName 是同一脚本返回的函数表中的函数名，该函数接收 (ctx, data)。
ctx:cancel(id)取消同一单位、同一技能尚未开始的任务。成功返回 true，已执行、已取消或属于别人的任务返回 false。
ctx.frame / ctx.taskId当前游戏帧和当前定时任务 ID。定时回调里的 self 是存活的施法者，target 是原事件对方，已移除时为 nil。
data创建任务时复制。可传 nil、布尔值、整数、有限小数、字符串、单位句柄，以及由整数或字符串作键的普通表。每次传递独立，循环表和函数不能保存。
ctx.state.key按单位和技能保存，可存与 data 相同的值。可存任务 ID 供后续事件取消。读取表会得到副本，修改后需要整项写回；赋 nil 清除。

地图格与同步随机

参数或接口说明
unit:position()返回地图格坐标 {x=..., y=...}。单位未在场上时返回 nil。
ctx:randomInt(min, max)在两端均包含的 32 位整数范围内同步抽取。Lua 随机序列由对局种子初始化，状态随存档保存。
ctx:randomPoint(area)area={center=格坐标, radius=整数格数}。半径 0～128，在圆形区域内等概率选一个可用地图格，地图边缘自动裁切。
Target = pointDetonateWarhead、FireWeapon、SpawnUnit、SpawnCrate、PlayAnim、PlaySound、ShakeScreen、SpawnParticleSystem 的 Target 可直接填写格坐标。引爆使用该格的地面或桥面高度。

示例

V3 开火后连续轰炸

开火时锁定目标位置，先引爆第一发，此后每 4 帧在半径 3 格内重新选点，合计 20 发。

额外补充说明

同一帧到期的任务按创建顺序执行。任务、传入的数据和随机进度随存档保存，读档后从上次进度继续。

施法者被移除时，其任务和状态一并清理。施法者只失去技能时，已安排的任务继续执行。定时回调可重新查询单位句柄；待扣伤害和载员消耗记录仅在原动作结算期间有效。

配套文件见示例 INI 和 AreaBarrage.lua。

Lua 可移动动画

Lua 脚本可以创建动画，取得整数句柄后平滑移动或移除同一个动画。使用游戏或模组已注册且具有有效图片的原生动画类型。

自定义动画应先通过游戏的常规规则和 art 配置注册，再把动画 ID 传给流火。接口使用动画类型 ID，不使用图片文件名。

接口与参数

接口说明
ctx:spawnAnim(id, point, options)在小数或整数地图格 {x=...,y=...} 创建动画，成功返回整数句柄，类型、图片或位置无效时返回 nil。loop 默认 false；duration 为 1～54000 游戏帧，默认 150；height 为相对地面高度，单位格，范围 -64～64，默认 0。
ctx:moveAnim(handle, point, frames)在 1～54000 帧内从当前位置线性移动到目标点，保持创建时的高度偏移，并替换当前移动。成功返回 true，无效句柄或位置返回 false。
ctx:removeAnim(handle)提前移除动画；成功返回 true，nil、过期或无权限的句柄返回 false。

句柄可保存在定时任务 data 或 ctx.state 中。普通技能按单位与技能限定权限，超武脚本按当次发动和动作限定；存档保留句柄、剩余时长和移动进度。施法单位死亡或移除时清理；超武动画按显式移除或时长清理。失去被动但单位仍存活时，动画不会立即移除。非循环动画可能早于保底时长播放完毕；同时最多管理 2048 个 Lua 动画。

示例

动画仅影响画面，联机玩家须使用相同配置和资源。龙卷风示例使用原生 PIFF 动画占位，可将 Script.Param.Anim 替换为模组已注册的动画 ID。完整示例见 示例 INI 和 Lua 脚本。
